# 理发店SaaS管理系统 - 项目分析报告

## 一、项目概述

本项目是一个基于Spring Boot框架开发的理发店SaaS管理系统，为理发店商家提供完整的店铺管理解决方案，包括商家管理、会员管理、理发师管理、消费管理和发型管理五大核心功能模块。

### 技术栈
- **后端框架**: Spring Boot
- **数据持久化**: Spring Data JPA
- **安全认证**: JWT (JSON Web Token)
- **API文档**: Swagger/OpenAPI
- **数据库**: 关系型数据库 (通过JPA支持)

---

## 二、主要功能模块

### 2.1 商家管理模块
商家管理模块负责商家的注册申请、审核、登录以及状态管理。

### 2.2 会员管理模块
会员管理模块负责会员信息的录入、充值、消费记录查询以及会员等级管理。

### 2.3 理发师管理模块
理发师管理模块负责理发师信息的增删改查、级别设置和状态管理。

### 2.4 消费管理模块
消费管理模块负责消费记录的创建、查询以及理发师匹配功能。

### 2.5 发型管理模块
发型管理模块负责发型类型和发型选项的管理，支持分类和状态控制。

---

## 三、功能流程与接口调用

### 3.1 商家管理模块

#### 3.1.1 商家注册功能

**功能概述**: 商家通过填写店铺信息提交注册申请，系统校验用户名唯一性后创建待审核状态的商家账号。

**业务流程**:
1. 商家填写注册信息（用户名、密码、店铺名称、联系电话等）
2. 系统校验用户名是否已存在
3. 密码加密存储
4. 创建商家记录，状态设为PENDING（待审核）
5. 返回注册成功提示

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `POST /api/merchants/register` | POST | 提交商家注册申请 |

---

#### 3.1.2 管理员审核功能

**功能概述**: 管理员查看待审核商家列表，对商家申请进行审核通过或拒绝操作。

**业务流程**:
1. 管理员获取待审核商家列表（支持分页）
2. 查看商家详细信息（店铺名称、地址、营业执照等）
3. 选择审核通过或拒绝
4. 通过：商家状态变为APPROVED，记录审核时间
5. 拒绝：商家状态变为REJECTED

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `GET /api/merchants/pending` | GET | 获取待审核商家列表（分页） |
| `GET /api/merchants/{id}` | GET | 获取商家详情信息 |
| `POST /api/merchants/{id}/approve` | POST | 审核通过商家申请 |
| `POST /api/merchants/{id}/reject` | POST | 拒绝商家申请 |

---

#### 3.1.3 商家登录功能

**功能概述**: 已审核通过的商家通过用户名密码登录系统，获取JWT认证令牌。

**业务流程**:
1. 商家输入用户名和密码
2. 系统验证用户名是否存在
3. 验证密码是否正确
4. 检查商家状态（PENDING/REJECTED/OFFLINE状态无法登录）
5. 生成JWT Token返回给前端
6. 后续请求需携带Token进行认证

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `POST /api/merchants/login` | POST | 商家登录获取Token |

---

#### 3.1.4 商家状态管理功能

**功能概述**: 管理员或商家可控制店铺的上线/下线状态，影响店铺是否对外营业。

**业务流程**:
1. 检查商家当前状态是否允许操作
2. 上线：状态从APPROVED/OFFLINE变为ONLINE
3. 下线：状态从ONLINE/APPROVED变为OFFLINE
4. 更新商家状态并返回结果

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `POST /api/merchants/{id}/online` | POST | 商家上线营业 |
| `POST /api/merchants/{id}/offline` | POST | 商家下线停业 |

---

#### 3.1.5 商家信息查询功能

**功能概述**: 管理员查看系统中所有商家信息，支持分页查询。

**业务流程**:
1. 指定分页参数（页码、每页数量）
2. 按创建时间倒序返回商家列表
3. 包含商家的完整信息（状态、余额、审核时间等）

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `GET /api/merchants` | GET | 获取所有商家列表（分页） |
| `GET /api/merchants/{id}` | GET | 获取单个商家详情 |

---

### 3.2 会员管理模块

#### 3.2.1 会员录入功能

**功能概述**: 商家录入新会员信息，系统校验手机号唯一性后创建会员账号。

**业务流程**:
1. 商家输入会员姓名和手机号
2. 系统校验该商家下手机号是否已注册
3. 创建会员记录，初始等级为NORMAL
4. 初始余额和累计消费均为0

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `POST /api/members` | POST | 创建新会员 |

---

#### 3.2.2 会员查询功能

**功能概述**: 商家查询自己店铺下的会员信息，支持列表查询、详情查询和手机号查询。

**业务流程**:
1. 列表查询：分页获取所有会员，按创建时间倒序
2. 详情查询：根据会员ID获取完整信息
3. 手机号查询：快速定位会员，便于消费时查找

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `GET /api/members` | GET | 获取会员列表（分页） |
| `GET /api/members/{id}` | GET | 获取会员详情 |
| `GET /api/members/phone/{phone}` | GET | 根据手机号查询会员 |

---

#### 3.2.3 会员充值功能

**功能概述**: 商家为会员账户充值，增加会员余额并记录交易流水。

**业务流程**:
1. 选择要充值的会员
2. 输入充值金额和备注
3. 校验会员归属（必须是当前商家的会员）
4. 增加会员余额
5. 创建交易记录（类型：RECHARGE）
6. 返回交易详情

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `POST /api/members/recharge` | POST | 会员充值 |

---

#### 3.2.4 交易记录查询功能

**功能概述**: 查询会员的充值和消费交易记录，支持按会员筛选。

**业务流程**:
1. 可选择指定会员ID进行筛选
2. 不指定则查询当前商家所有交易记录
3. 按创建时间倒序返回
4. 包含交易类型、金额、余额变化等信息

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `GET /api/members/transactions` | GET | 获取交易记录列表（分页） |

---

#### 3.2.5 会员等级管理功能

**功能概述**: 支持手动调整会员等级，会员等级影响消费折扣。

**业务流程**:
1. 选择要调整的会员
2. 指定新的会员等级
3. 校验会员归属
4. 更新会员等级

**自动升级规则**: 系统会在消费时自动根据累计消费金额升级会员等级：
- 累计消费 ≥ 500元 → 银卡会员
- 累计消费 ≥ 2000元 → 金卡会员
- 累计消费 ≥ 5000元 → 白金会员
- 累计消费 ≥ 10000元 → 钻石会员

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `PUT /api/members/{id}/level` | PUT | 手动更新会员等级 |

---

### 3.3 理发师管理模块

---

**业务流程**:
1. 列表查询：分页获取所有理发师

#### 3.3.3 理发师信息维护功能

**功能概述**: 商家修改理发师的基本信息，包括姓名、电话、级别和提成比例。

**业务流程**:
1. 选择要修改的理发师
2. 校验理发师归属
3. 更新理发师信息
4. 返回更新后的理发师信息

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `PUT /api/barbers/{id}` | PUT | 更新理发师信息 |

---

1. 校验理发师归属
2. 删除理发师记录
3. 注意：删除后历史消费记录仍保留理发师ID

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `DELETE /api/barbers/{id}` | DELETE | 删除理发师 |

### 3.4 消费管理模块

#### 3.4.1 理发师智能匹配功能

**功能概述**: 根据会员选择的发型类型和选项，智能推荐最适合的理发师。

**业务流程**:
1. 会员选择发型类型和发型选项
2. 系统获取当前商家所有活跃理发师
3. 根据理发师级别计算匹配分数：
   - 首席理发师：5分
   - 大师理发师：4分
   - 高级理发师：3分
   - 中级理发师：2分
   - 初级理发师：1分
4. 按匹配分数倒序返回推荐列表

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `POST /api/consumptions/match-barber` | POST | 匹配推荐理发师 |

---

#### 3.4.2 消费记录创建功能

**功能概述**: 记录会员消费，自动计算会员折扣和理发师提成。

**业务流程**:
1. 选择会员和理发师
2. 输入原价金额
3. 选择支付方式（余额/现金/银行卡/其他）
4. 可选选择发型类型和发型选项
5. 系统自动计算：
   - 根据会员等级计算折扣金额
   - 实际支付金额 = 原价 × 会员折扣率
   - 理发师提成 = 实际支付金额 × 提成比例
6. 余额支付时扣除会员余额
7. 更新会员累计消费金额
8. 自动升级会员等级（如满足条件）
9. 创建消费记录
10. 创建交易记录（类型：CONSUME）

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `POST /api/consumptions` | POST | 创建消费记录 |

---

#### 3.4.3 消费记录查询功能

**功能概述**: 商家查询消费记录，支持按会员或理发师筛选。

**业务流程**:
1. 按会员筛选：查询指定会员的消费记录
2. 按理发师筛选：查询指定理发师的服务记录
3. 全部查询：不指定条件查询所有消费记录
4. 返回完整消费信息（会员名、理发师名、金额、折扣等）

**涉及接口**:

| 接口路径 | 方法 | 功能描述 |
|---------|------|---------|
| `GET /api/consumptions` | GET | 获取消费记录列表（分页） |
| `GET /api/consumptions/barber/{barberId}` | GET | 获取理发师的消费记录（分页） |

## 四、接口详细描述

### 4.1 商家管理接口

#### 4.1.1 商家注册申请

**接口路径**: `POST /api/merchants/register`

**功能描述**: 商家提交注册申请，等待管理员审核。注册成功后商家状态为PENDING（待审核）。

**请求参数**:

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|-----|------|
| username | String | 是 | 用户名，长度3-50字符 |
| password | String | 是 | 密码，长度6-100字符 |
| shopName | String | 是 | 店铺名称 |
| address | String | 否 | 店铺地址 |
| phone | String | 是 | 联系电话 |
| contactPerson | String | 否 | 联系人 |
| businessLicense | String | 否 | 营业执照 |

**返回参数**:

| 字段名 | 类型 | 说明 |
|-------|------|------|
| code | int | 响应状态码 |
| message | String | 响应消息 |
| data | MerchantResponse | 商家信息对象 |

**MerchantResponse对象字段**:

| 字段名 | 类型 | 说明 |
|-------|------|------|
| id | Long | 商家ID |
| username | String | 用户名 |
| shopName | String | 店铺名称 |
| address | String | 店铺地址 |
| phone | String | 联系电话 |
| contactPerson | String | 联系人 |
| businessLicense | String | 营业执照 |
| status | MerchantStatus | 商家状态 |
| balance | BigDecimal | 账户余额 |
| createdAt | LocalDateTime | 创建时间 |
| approvedAt | LocalDateTime | 审核通过时间 |

**商家状态枚举(MerchantStatus)**:

| 值 | 说明 |
|---|------|
| PENDING | 待审核 |
| APPROVED | 已审核 |
| REJECTED | 已拒绝 |
| ONLINE | 已上线 |
| OFFLINE | 已下线 |

---

#### 4.1.2 商家登录

**接口路径**: `POST /api/merchants/login`

**功能描述**: 商家登录获取JWT Token，用于后续接口认证。

**请求参数**:

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|-----|------|
| username | String | 是 | 用户名 |
| password | String | 是 | 密码 |

**返回参数**:

| 字段名 | 类型 | 说明 |
|-------|------|------|
| code | int | 响应状态码 |
| message | String | 响应消息 |

**LoginResponse对象字段**:

| 字段名 | 类型 | 说明 |

#### 4.1.3 获取待审核商家列表

**接口路径**: `GET /api/merchants/pending`

**功能描述**: 管理员获取待审核的商家列表，支持分页。

**请求参数**:

| 字段名 | 类型 | 必填 | 默认值 | 说明 |

| size | int | 否 | 10 | 每页数量 |

**返回参数**:

| 字段名 | 类型 | 说明 |
|-------|------|------|
| code | int | 响应状态码 |
| message | String | 响应消息 |
| data | Page<MerchantResponse> | 分页商家列表 |

## 六、业务规则说明

### 6.1 会员等级自动升级规则

| 累计消费金额 | 会员等级 |
|------------|---------|
| ≥ 500元 | 银卡会员 (SILVER) |
| ≥ 2000元 | 金卡会员 (GOLD) |
| ≥ 5000元 | 白金会员 (PLATINUM) |
| ≥ 10000元 | 钻石会员 (DIAMOND) |

### 6.2 会员折扣规则

| 会员等级 | 折扣率 |
|---------|-------|
| 普通会员 (NORMAL) | 1.0（无折扣） |
| 银卡会员 (SILVER) | 0.95（95折） |
| 金卡会员 (GOLD) | 0.9（9折） |
| 白金会员 (PLATINUM) | 0.85（85折） |
| 钻石会员 (DIAMOND) | 0.8（8折） |

### 6.3 理发师提成规则

理发师提成 = 实际支付金额 × 提成比例

默认提成比例为30%，可在创建或更新理发师时设置。

### 6.4 商家状态流转

```
注册申请 → PENDING（待审核）
    ↓
审核通过 → APPROVED（已审核）
    ↓
上线 → ONLINE（已上线）
    ↓
下线 → OFFLINE（已下线）

审核拒绝 → REJECTED（已拒绝）
```

## 八、认证说明

系统采用JWT（JSON Web Token）进行身份认证。

1. 商家通过登录接口获取Token
2. 后续请求需在请求头中携带Token：
   ```
   Authorization: Bearer <token>
   ```
3. Token包含商家ID和用户名信息
4. 系统会验证Token的有效性和商家状态
